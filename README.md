# Wortschatz

PWA для набора немецкого словарного запаса: 10 000 самых частотных лемм
(ориентир — C1) с переводом на русский и английский, работает офлайн.

Всё в контейнерах: на машине нужен только Docker.

## Запуск локально

```bash
docker compose up -d --build
open http://localhost:8080
```

Порт меняется переменной `PORT` (см. `.env.example`).

## Деплой на VPS

Нужен Docker и домен, A-запись которого смотрит на сервер.

```bash
git clone <репозиторий> wortschatz && cd wortschatz
cp .env.example .env && nano .env        # вписать свой DOMAIN
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Caddy сам получит сертификат Let's Encrypt и будет его продлевать.
HTTPS здесь не украшение: без него браузер не зарегистрирует service worker,
а значит не будет ни офлайна, ни установки приложения на телефон.

Обновление — обычный `git pull`:

```bash
git pull && docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Собранный `app/wortschatz.db` лежит в репозитории, поэтому на сервере
ничего парсить и качать не нужно.

## Пересборка словаря

Нужна, только если меняются источники или логика отбора слов.
Python и зависимости ставить не надо — всё внутри контейнера:

```bash
docker compose run --rm builder
```

Скачает дампы в `data/` (~1,1 ГБ, кэшируется) и перезапишет `app/wortschatz.db`.
Дальше — пересобрать образ `web`, чтобы новая база попала внутрь.

## Как собран словарь

| источник | размер | что даёт |
|---|---|---|
| `de_50k.txt` | 1 МБ | частотность словоформ (OpenSubtitles) |
| `kaikki-de.jsonl` | 1 ГБ | английские значения, род, мн. ч., IPA, примеры |
| `kaikki-ru.jsonl` | 108 МБ | русские значения |

Ключевая деталь: ранжируются **леммы**, а не словоформы. Из Wiktionary берётся
таблица форм каждой леммы, и частоты всех форм суммируются
(`ist` + `war` + `bin` + `gewesen` → `sein`). Иначе топ-10000 забивается
спряжениями десятка глаголов вместо новых слов. Омографы делят частоту поровну.

Две ловушки, которые пришлось обойти (обе искажали рейтинг целиком):

* в таблицах сложных времён вспомогательный глагол стоит отдельной формой
  (`habe geäugt` → форма `haben`), из-за чего частота `haben` размазывалась
  по всем глаголам языка — отсекается по метке `auxiliary`;
* у служебных слов Wiktionary ставит первым грамматическое описание
  (`sein` → «forms the present perfect»), поэтому главное значение выбирается
  по оценке, а не по порядку.

Итог: 10 000 слов, 4,7 МБ (2 МБ по сети в gzip). Русский перевод у 85%,
IPA у 87%, род у 99,5% существительных, пример с переводом у 32%.

## Как устроено приложение

`app/wortschatz.db` скачивается браузером целиком и открывается через
**sql.js** — SQLite, скомпилированный в WebAssembly. Сервер для запросов
не нужен, всё работает на клиенте.

SQLite синхронен, а загрузка базы занимает сотни миллисекунд, поэтому он
вынесен в **Web Worker** (`app/js/db-worker.js`) — иначе интерфейс
подвисал бы при старте.

Словарь доступен только на чтение и заменяется целиком при обновлении,
поэтому прогресс обучения в нём не хранится — он будет жить отдельно
в IndexedDB.

## Структура

```
app/              то, что раздаётся nginx
  index.html
  css/ js/        интерфейс и воркер с SQLite
  vendor/         sql.js (wasm), вкомпилирован в репозиторий ради офлайна
  wortschatz.db   собранный словарь
  sw.js           офлайн-кэш
scripts/
  fetch_sources.sh  качает дампы в data/
  build_db.py       собирает базу (только стандартная библиотека Python)
data/             сырые дампы, в git не хранятся
```
